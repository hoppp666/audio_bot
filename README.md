# VK News Bot - автопостинг зарубежных новостей в группу ВКонтакте

Конвейер: RSS-ленты -> фильтры и дедупликация -> перевод на русский ->
скачивание картинок -> публикация на стену группы через VK API.

Пост собирается так: эмодзи рубрики, заголовок, 2-3 абзаца текста, хэштеги,
строка "Фото: <источник>", под постом - ссылка на оригинал и 1-2 фотографии.

---

## Шаг 1. Узнать ID группы

Скрипту нужен ЧИСЛОВОЙ ID (например `59817233`), минус он добавит сам.

- Если в адресной строке `vk.com/club59817233` или `vk.com/public59817233` -
  это и есть ID: цифры после `club`/`public`.
- Если у группы короткий адрес (например `vk.com/yourfashion`) - зайдите в
  группу как администратор и откройте **Управление**: в адресной строке
  появится `vk.com/clubXXXXXX?act=...`, где XXXXXX - нужный ID.
- Альтернатива без настроек: откройте любое фото группы - ссылка вида
  `https://vk.com/album-59817233_00` содержит ID со знаком минус
  (`-59817233`); в скрипт вписывайте число без минуса.

## Шаг 2. Получить токен сообщества

Самый простой способ - токен самой группы (создавать приложение не нужно):

1. Откройте группу -> **Управление** -> **Работа с API** (если пункта нет -
   сначала включите его в разделе Управление -> Настройки или используйте
   альтернативу из шага 2а).
2. **Ключи доступа** -> **Создать ключ**.
3. Отметьте права:
   - **Фотографии** (управление фотографиями сообщества),
   - **Стена** (создание и редактирование записей),
   - **Документы** (по желанию, для будущих нужд).
4. Создайте и сразу скопируйте ключ - он показывается **один раз**.
   Выглядит как длинная строка вида `vk1.a.XXXXX...`.

Токен сообщества умеет всё, что нужно боту: постить на стену от имени
группы и загружать фотографии на стену.

### 2а. Альтернатива: пользовательский токен через standalone-приложение

Если пункт "Работа с API" недоступен (старый интерфейс или ограничения):

1. Создайте приложение на https://vk.com/apps?act=manage - тип
   **Standalone**, название любое.
2. Подставьте свой `APP_ID` в ссылку и откройте её в браузере:
   `https://oauth.vk.com/authorize?client_id=APP_ID&display=page&scope=wall,photos,groups,offline&response_type=token&v=5.199`
3. Разрешите доступ (нужно быть администратором группы) - токен появится в
   адресной строке после `access_token=`. Скопируйте его целиком.

## Шаг 3. Установка и настройка

Нужен Python 3.10+ (на Windows - галочка "Add Python to PATH" при установке).

```bash
cd vk-news-bot
python3 -m venv .venv

# Linux/macOS:
source .venv/bin/activate
# Windows:
.venv\Scripts\activate

pip install -r requirements.txt
cp .env.example .env
```

Откройте `.env` и впишите:

```
VK_TOKEN=vk1.a.XXXXX...
GROUP_ID=59817233
```

Токен никому не показывайте и не публикуйте (в том числе в этом чате) -
он даёт полный доступ к стене группы. Если ключ утёк - удалите его в
Управление -> Работа с API и создайте новый.

## Шаг 4. Пробный запуск (без публикации)

```bash
python3 vk_news_bot.py
```

Бот обойдёт все ленты из `sources.yaml`, отфильтрует и переведёт новости и
сложит готовые посты в папку `drafts/` (файл `.md`: текст поста + список
картинок). Посмотрите, нравится ли вам стиль.

Что можно подкрутить в `sources.yaml`:
- `posts_per_run` - сколько постов за один запуск;
- `images_per_post` - сколько фото в посте;
- `require_image: false` - разрешить посты без картинки;
- `include_link: false` - не прикладывать ссылку на оригинал;
- рубрики (`emoji`, `hashtags`) и стоп-слова (`global_exclude`);
- любой источник можно отключить: `enabled: false`.

## Шаг 5. Настоящая публикация

```bash
python3 vk_news_bot.py --post
```

Посты появятся на стене группы от её имени. Если за запуск публикуется
несколько постов, остальные уйдут с отложкой (`stagger_minutes`, по
умолчанию 40 минут) - это штатная отложка ВКонтакте, посты видны в разделе
Запланированные.

## Шаг 6. Автоматизация

Linux/macOS - cron (проверять ленты каждые 2 часа):

```bash
crontab -e
# добавьте строку (пути подставьте свои):
0 */2 * * * cd /home/user/vk-news-bot && .venv/bin/python vk_news_bot.py --post >> logs/cron.log 2>&1
```

Windows - Планировщик заданий: новая задача -> триггер "Каждые 2 часа" ->
действие "Запуск программы": `python.exe` с аргументами
`vk_news_bot.py --post` и рабочей папкой проекта.

При `posts_per_run: 2` и запуске раз в 2 часа получится до 24 постов в
сутки - это выше лимита VK (~20 постов в сутки на стену сообщества через
API). Рекомендуемый ритм: `posts_per_run: 2` раз в 3 часа (16 постов), либо
раз в 2 часа с `posts_per_run: 1-2` и следить за ошибками 6/15 в логе.

## Запуск на GitHub Actions (бесплатно, без своего компьютера)

Бот будет работать на серверах GitHub по расписанию: ничего скачивать и
устанавливать на свой компьютер не нужно. Токен хранится в зашифрованных
Secrets репозитория. Дедупликация работает через стену группы (бот помнит
последние ~50 своих постов), поэтому постоянный диск не требуется.

### 1. Создайте аккаунт и репозиторий

1. Зарегистрируйтесь на github.com (если аккаунта ещё нет).
2. Нажмите **+** в правом верхнем углу -> **New repository**.
3. Название: `vk-news-bot`, видимость: **Private** (бесплатно хватит: ~1800
   минут/мес при запуске раз в 2 часа; в публичном репозитории минуты не
   ограничены, но код увидят все).
4. Нажмите **Create repository**.

### 2. Загрузите файлы проекта

1. На открывшейся пустой странице репозитория нажмите ссылку
   **uploading an existing file**.
2. Перетащите из распакованного архива 4 файла:
   `vk_news_bot.py`, `sources.yaml`, `requirements.txt`, `README.md`.
3. Нажмите **Commit changes**.

### 3. Добавьте файл воркфлоу

1. В репозитории: **Add file** -> **Create new file**.
2. В поле имени файла введите: `.github/workflows/post.yml` - при вводе
   слэшей GitHub сам создаст папки.
3. Вставьте содержимое файла `.github/workflows/post.yml` из архива.
4. **Commit changes** (кнопка сверху справа).

### 4. Впишите секреты

1. В репозитории: **Settings** -> **Secrets and variables** -> **Actions**.
2. **New repository secret** -> Name: `VK_TOKEN`, Secret: ваш токен -> Add.
3. Ещё раз: Name: `GROUP_ID`, Secret: число без минуса -> Add.
4. (Необязательно) `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL` - для
   редактуры постов нейросетью.

### 5. Первый запуск и проверка

1. Откройте вкладку **Actions** в репозитории.
2. Слева выберите **VK news bot**, справа нажмите **Run workflow** -> **Run**.
3. Кликните на запустившийся процесс -> **Publish to VK** и смотрите лог:
   увидите, какие новости найдены, переведены и опубликованы.
4. Загляните в группу - посты должны появиться на стене.

После первого запуска расписание стартует само (каждые 2 часа по UTC, т.е.
в 9:00, 11:00, 13:00... по Москве). GitHub иногда сдвигает запуск на
несколько минут - это нормально.

### 6. Обслуживание

- **Расписание отключается, если 60 дней не трогать репозиторий** -
  достаточно любого изменения (например, поправить sources.yaml).
- Одновременный запуск возможен только одной копии воркфлоу
  (concurrency-группа в `post.yml`): запуски не пересекаются, VK не отвечает
  flood control, а `git push` не ловит конфликт "fetch first". База
  `seen.sqlite` коммитится только когда бот реально что-то записал.
- Проверять бота удобно в той же вкладке Actions: зелёная галочка -
  прогон прошёл, красный крест - откройте лог и посмотрите причину.
- Изменить частоту: откройте `.github/workflows/post.yml`, строка
  `cron: "0 */2 * * *"` - это UTC, Москва = UTC+3 (запуск в 9:00 по Москве
  = `0 6 * * *`).
- Изменить число постов за прогон: в `sources.yaml`, `posts_per_run`
  (следите за лимитом VK ~20 постов/сутки).
- Ошибки вида `error 6` (слишком часто) - увеличьте интервал cron.
- Токен скомпрометирован? Удалите ключ в группе (Управление -> Работа с
  API) и обновите секрет VK_TOKEN.

## Опционально: живая редактура через LLM

Машинный перевод корректный, но сухой. Если в `.env` задать `LLM_API_KEY`
(любая OpenAI-совместимая API: OpenRouter, GLM и т.п.), каждый пост будет
переписан моделью: цепляющий заголовок + 2-3 абзаца в стиле паблика.

```
LLM_API_KEY=sk-...
LLM_BASE_URL=https://openrouter.ai/api/v1
LLM_MODEL=openai/gpt-4o-mini
```

Без ключа работает обычный перевод (Google Translate с запасным
MyMemory) - тоже вполне рабочий вариант.

## Как это работает внутри

- **Дедупликация**: база `data/seen.sqlite` хранит URL и заголовки
  опубликованного. Отсекаются повторные URL, точные совпадения заголовков и
  похожие (>76% совпадения) - Just Jared и Daily Mail часто пишут об одном
  и том же.
- **Картинки**: сначала берутся из самой ленты (media/enclosure/img),
  если там пусто - `og:image` со страницы статьи. Слишком мелкие отбрасываются,
  большие сжимаются до 1600px, всё конвертируется в JPEG.
- **Фильтры**: возраст новости (`max_age_hours`), стоп-слова (глобальные и
  по-источниково), для Rolling Stone - белый список музыкальных тем, чтобы
  политика не попадала в группу.
- После 3 неудачных попыток публикации URL больше не трогается.

## Если что-то не работает

| Симптом | Причина и что делать |
|---|---|
| `VK лимит (9) на wall.get` | временный flood control: бот пропустит синхронизацию истории и продолжит работу по локальной базе. Не запускайте ручные прогоны подряд и не гоняйте бота локально с тем же токеном во время Actions |
| `! [rejected] main -> main (fetch first)` | если такое увидели - workflow сам сливает базы через `tools/merge_seen_db.py` и повторяет push до 3 раз; убедитесь, что файл `tools/merge_seen_db.py` добавлен в репозиторий |
| `error 15: Access denied` | токен без права "Стена" - пересоздайте ключ |
| `ошибка 27` при загрузке фото | токен сообщества: VK не даёт загружать фото через API (ограничение с 2026) - бот сам опубликует новость текстом без картинок; для постов с фото нужен пользовательский токен |
| `error 6: Too many requests` | слишком часто: уменьшите частоту cron или posts_per_run |
| `error 100` в wall.post | проверьте GROUP_ID (число без минуса) |
| "перевод недоступен" | сеть режет translate.google.com; поставьте LLM_API_KEY или повторите позже |
| "лента недоступна" | сайт изменил URL ленты или блокирует - проверьте URL в браузере, временно поставьте `enabled: false` |
| В drafts/ пусто | всё уже опубликовано или отфильтровано; смотрите logs/bot.log - там причина по каждой записи |

Полезно: `python3 vk_news_bot.py --reset-db` - забыть всё опубликованное
(например, после смены рубрик, чтобы перепроверить фильтры).
